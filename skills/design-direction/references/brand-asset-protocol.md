# 核心資產協議

> `design-direction` §圖片是不是必需 的延伸：**設計裡要出現具名的第三方產品或品牌時**，走這份協議。
> 這裡是完整的 5 步操作、下載命令、資產清單樣板、失敗兜底、反例與代價對比。

**這是穩定性的生命線。** 有沒有走通這個協議，直接決定產出是 40 分還是 90 分。不要跳過任何一步。

**觸發條件**：設計裡點名或並列了具體品牌／產品（自家公司也算），**不論對方是否主動提供了品牌資料**。

**前置硬條件**：走協議前必須先確認該品牌／產品存在且狀態已知（依 rules.md §事實核實）。還不確定產品是否已發表／規格／版本，先回去查。

## 核心理念：資產 > 規範

**品牌的本質是「它被認出來」**。認出來靠什麼？按辨識度排序：

| 資產類型 | 辨識度貢獻 | 必需性 |
|---|---|---|
| **Logo** | 最高 · 任何品牌出現 logo 就一眼辨識 | **任何品牌都必須有** |
| **產品圖／產品算圖** | 極高 · 實體產品的「主角」就是產品本身 | **實體產品（硬體／包裝／消費品）必須有** |
| **UI 截圖／介面素材** | 極高 · 數位產品的「主角」是它的介面 | **數位產品（App／網站／SaaS）必須有** |
| **色值** | 中 · 輔助辨識，脫離前三項時經常撞衫 | 輔助 |
| **字型** | 低 · 需配合前述才能建立辨識 | 輔助 |
| **氣質關鍵字** | 低 · 自檢用 | 輔助 |

**翻譯成執行規則**：
- 只抽色值 ＋ 字型、不找 logo／產品圖／UI → **違反本協議**
- 用 CSS 剪影／SVG 手畫替代真實產品圖 → **違反本協議**（做出來的就是「通用科技畫面」，任何品牌都長一樣）
- 找不到資產不說、硬做 → **違反本協議**
- 寧可停下來要素材，也不要用 generic 填充

## 5 步硬流程（每步有 fallback，絕不靜默跳過）

### Step 1 · 問（資產清單一次問全）

不要只問「有 brand guidelines 嗎？」——太寬泛，對方不知道該給什麼。按清單逐項問：

```
關於 <brand/product>，你手上有以下哪些資料？我按優先序列：
1. Logo（SVG／高清 PNG）—— 任何品牌必備
2. 產品圖／官方算圖 —— 實體產品必備
3. UI 截圖／介面素材 —— 數位產品必備
4. 色值清單（HEX／RGB／品牌色盤）
5. 字型清單（Display／Body）
6. Brand guidelines PDF／設計系統檔／品牌官網連結

有的直接給我，沒有的我去搜／抓。
```

### Step 2 · 搜官方管道（按資產類型）

| 資產 | 搜尋路徑 |
|---|---|
| **Logo** | `<brand>.com/brand` · `<brand>.com/press` · `<brand>.com/press-kit` · `brand.<brand>.com` · 官網 header 的 inline SVG |
| **產品圖／算圖** | 官方產品詳情頁的 hero image ＋ gallery · 官方發表影片截格 · 官方新聞稿附圖 |
| **UI 截圖** | App Store／Google Play 產品頁截圖 · 官網 screenshots section · 產品官方展示影片截格 |
| **色值** | 官網 inline CSS／設定檔／brand guidelines PDF |
| **字型** | 官網 `<link rel="stylesheet">` 引用 · 網頁載入的字型來源 · brand guidelines |

搜尋兜底關鍵字：
- Logo 找不到 → `<brand> logo download SVG`、`<brand> press kit`
- 產品圖找不到 → `<brand> <product> official renders`、`<brand> <product> product photography`
- UI 找不到 → `<brand> app screenshots`、`<brand> dashboard UI`

### Step 3 · 下載資產 · 按類型三條兜底路徑

#### 3.1 Logo（任何品牌必需）

> **別只試 `curl <brand>.com/logo.svg` 就放棄**——現在的官網大多是 SPA，直連靜態路徑基本回空殼 HTML（2026-06 實測某官網 5 條直連路徑全是空殼）。**數位產品／SaaS／AI 工具優先用圖示聚合來源**，命中率最高、直出乾淨 SVG。

按成功率遞減：

0. **圖示聚合來源（知名數位產品／SaaS／AI 工具首選，命中率最高）**：
   ```bash
   # 某些網路環境下 proxy 會讓 TLS 失敗，必要時先清掉再試
   curl -s "https://api.svgl.app?search=<brand>"   # 回 JSON，取 route(.light/.dark) 的 svg URL 再下載
   curl -o logo.svg "https://cdn.simpleicons.org/<slug>/<hexcolor>"   # 單色 glyph，可直接上品牌色
   ```
1. 獨立 SVG／PNG 檔／官方 brand 頁：
   ```bash
   curl -A "Mozilla/5.0" -L -o <資產目錄>/logo.svg "<official-logo-url>"
   ```
2. 官網 HTML 全文提取 inline SVG：
   ```bash
   curl -A "Mozilla/5.0" -L "https://<brand>.com" -o <資產目錄>/homepage.html
   # 然後 grep <svg>...</svg> 提取 logo 節點
   ```
3. **favicon 服務（站點真實 mark 兜底，幾乎不失敗）**：
   ```bash
   curl -o logo.png "https://www.google.com/s2/favicons?domain=<brand-domain>&sz=256"
   ```
4. 官方社群帳號 avatar（最後手段）：公司頭像通常是 400×400 或 800×800 透明底 PNG

下載後**逐個核對**：`file <logo>` 確認是真的 SVG／PNG（不是 106 位元組占位或 HTML 空殼），`head -c 90 <logo.svg>` 看開頭是不是 `<svg`。

#### 3.2 產品圖／算圖（實體產品必需）

按優先序：
1. **官方產品頁 hero image**（最高優先）：查看圖片位址／curl 取得。解析度通常 2000px+
2. **官方 press kit**：`<brand>.com/press` 常有高清產品圖下載
3. **官方發表影片截格**：需要影片下載與抽格工具；**本專案未預裝這類工具，沒有就跳過這條，不要現場安裝**
4. **Wikimedia Commons**：公共領域常有
5. **兜底**：向對方索取 → 都沒有就用**誠實 placeholder**（灰塊 ＋ 文字標籤，明確標註「產品圖待補」）。**不要用 CSS／SVG 手畫代替**

```bash
# 範例：下載官方產品頁的 hero image
curl -A "Mozilla/5.0" -L "<hero-image-url>" -o <資產目錄>/product-hero.png
```

#### 3.3 UI 截圖（數位產品必需）

- App Store／Google Play 的產品截圖（注意：可能是 mockup 而非真實 UI，要比對）
- 官網 screenshots section
- 產品展示影片截格
- 產品官方社群帳號的發表截圖（常是最新版本）
- 對方有帳號時，直接截真實產品介面

#### 3.4 素材品質門檻「5-10-2-8」原則（鐵律）

> **Logo 的規則不同於其他素材**。Logo 有就必須用（沒有就停下來問）；其他素材（產品圖／UI／參考圖／配圖）遵守「5-10-2-8」品質門檻：**搜尋 5 輪、找到 10 個素材、選 2 個好的，每個要 8/10 分以上——寧可少一些，也不為了完成任務濫竽充數。**

| 維度 | 標準 | 反模式 |
|---|---|---|
| **5 輪搜尋** | 多管道交叉搜（官網／press kit／官方社群／影片截格／Wikimedia／對方帳號截圖），不是一輪抓前 2 個就停 | 第一頁結果直接用 |
| **10 個候選** | 至少湊 10 個備選才開始篩 | 只抓 2 個，沒得選 |
| **選 2 個好的** | 從 10 個裡精選 2 個當最終素材 | 全都用 ＝ 視覺過載 ＋ 品味稀釋 |
| **每個 8/10 分以上** | 不夠 8 分**寧可不用**，改用誠實 placeholder（灰塊 ＋ 文字標籤） | 湊數的 7 分素材進資產清單 |

**8/10 評分維度**（打分時記進 `spec.md` 的資產清單）：

1. **解析度** · ≥2000px（大螢幕場景 ≥3000px）
2. **版權清晰度** · 官方來源 > 公共領域 > 免費素材 > 疑似盜圖（疑似盜圖直接 0 分）
3. **與品牌氣質契合度** · 和資產清單裡的「氣質關鍵字」一致
4. **光線／構圖／風格一致性** · 2 個素材放一起不打架
5. **獨立敘事能力** · 能單獨表達一個敘事角色（不是裝飾）

**為什麼這個門檻是鐵律**：
- **寧缺毋濫**。濫竽充數的素材比沒有更糟——汙染視覺品味、傳遞「不專業」訊號
- 這是「一個細節做到 120%，其餘做到 80%」的量化版：8 分是「其餘 80%」的底線，真正的 hero 素材要 9-10 分
- 看作品的人，對每一個視覺元素都在**加分或扣分**。7 分素材 ＝ 扣分項，不如留空

**Logo 例外**（重申）：有就必須用，不適用「5-10-2-8」。因為 logo 不是「多選一」問題，而是「辨識度根基」問題——就算 logo 本身只有 6 分，也比沒有 logo 強 10 倍。

### Step 4 · 驗證 ＋ 提取（不只是 grep 色值）

| 資產 | 驗證動作 |
|---|---|
| **Logo** | 檔案存在 ＋ SVG／PNG 可開 ＋ 至少兩個版本（深底／淺底用）＋ 透明背景 |
| **產品圖** | 至少一張 2000px+ ＋ 去背或乾淨背景 ＋ 多個角度（主視角、細節、場景） |
| **UI 截圖** | 解析度真實（1x／2x）＋ 是最新版本 ＋ **無他人資料汙染**（截圖裡的姓名／email／帳號一律遮蔽，見 rules.md §PII 安全底線） |
| **色值** | `grep -hoE '#[0-9A-Fa-f]{6}' <資產目錄>/*.{svg,html,css} \| sort \| uniq -c \| sort -rn \| head -20`，過濾黑白灰 |

**警惕示範品牌汙染**：產品截圖裡常有示範用的第三方品牌色，那不是該產品自己的色。**同時出現兩種強色時必須區分。**

**品牌多切面**：同一品牌的官網行銷色和產品 UI 色經常不同（例如官網暖米 ＋ 橙、產品 UI 是炭黑 ＋ 萊姆綠）。**兩套都是真的**——依交付場景選合適的切面。

### Step 5 · 把資產清單寫進 `spec.md`（不開獨立檔）

資產清單**寫進 `spec.md` 的「設計方向」段落之下**，不另外產生一份規格檔。為什麼：資產檔本身落在 `docs/work/<branch-name>/design-demos/assets/`（不進版控、隨 branch 消失），**能留下來的只有 `spec.md` 裡的來源記錄**；再開一個獨立檔只會多一份會過期、且同樣不進版控的東西。

清單要覆蓋的欄位：

```markdown
### 資產清單 · <Brand>
> 採集日期：YYYY-MM-DD ｜ 完整度：<完整 / 部分 / 推斷>

**核心資產**
- Logo 主版本 / 淺底反色版：<檔名> ← <來源網址>
- 產品圖（實體產品必填）：主視角 / 細節 / 場景 <檔名> ← <來源網址>
- UI 截圖（數位產品必填）：主頁 / 核心功能 <檔名> ← <來源網址>
- 各資產的 8/10 評分與使用場景

**輔助資產**
- 色板：Primary / Background / Ink / Accent，各附來源標註；禁用色
- 字型：Display / Body / Mono
- 簽名細節：哪些細節是「120% 做到」的
- 禁區：明確不能做的
- 氣質關鍵字：3-5 個形容詞
```

**寫完之後的執行紀律（硬要求）**：
- 三版 HTML 必須**引用清單裡的實際資產檔**，不允許用 CSS 剪影／SVG 手畫代替
- Logo 用 `<img>` 引用真實檔案，不重畫
- 產品圖用 `<img>` 引用真實檔案，不用 CSS 剪影代替
- CSS 變數從清單注入：`:root { --brand-primary: ...; }`，HTML 只用 `var(--brand-*)`
- 這讓品牌一致性從「靠自覺」變成「靠結構」——想臨時加色要先改清單

## 全流程失敗的兜底

| 缺失 | 處理 |
|---|---|
| **Logo 完全找不到** | **停下來問**，不要硬做（logo 是品牌辨識度的根基） |
| **產品圖（實體產品）找不到** | 向對方索取 → 都沒有就用誠實 placeholder（灰塊 ＋ 文字標籤，明確標註「產品圖待補」），並在三版說明裡註明 |
| **UI 截圖（數位產品）找不到** | 向對方索取自己帳號的截圖 → 官方展示影片截格。不用 mockup 產生器湊 |
| **色值完全找不到** | 走 `design-styles.md` §色彩推導協議 推導，並在產出裡標明這是推導不是品牌實色 |

**禁止**：找不到資產就靜默用 CSS 剪影／通用漸層硬做——這是本協議最大的反 pattern。**寧可停下來問，也不要湊。**

## 反例（真實踩過的坑）

- **憑記憶猜色**：憑印象認定某產品「應該是橙色」，實際是 `#1783FF` 藍色——整份返工
- **示範品牌汙染**：把產品截圖裡示範用的第三方品牌色，當成該產品自己的色——差點毀掉整個設計
- **只抽色值不取資產**：走了只抽色值的舊流程，沒下載 logo、沒找產品圖，用 CSS 剪影代替產品——做出來是「通用黑底 ＋ 橙 accent 的科技畫面」，完全沒有該品牌的辨識度。**這個案例正是本協議從「品牌資產」升級為「核心資產」的原因**：色值和字型是輔助，logo 與產品圖才是被認出來的根據
- **抽完色沒記下來**：抽完色沒寫進資產清單，第三頁就忘了主色數值，臨場加了個「接近但不是」的 hex——品牌一致性崩潰
- **並列多個產品卻一個 logo 都沒取**：做多產品對比的頁面時，把任務判成「沒有品牌參考」，只抽了各家品牌色就開始做，**五個產品 logo 一個沒取**。根因：把「對比／榜單」誤判為不觸發本協議（以為只管「為單一客戶做物料」）。→ 修正：觸發條件明訂含「設計裡點名或並列真實產品」，且無先例的路徑同樣不豁免取 logo

## 協議代價 vs 不做的代價

| 場景 | 時間 |
|---|---|
| 正確走完協議 | 下載 logo 5 min ＋ 下載 3-5 張產品圖／UI 10 min ＋ grep 色值 5 min ＋ 寫清單 10 min ＝ **30 分鐘** |
| 不做協議的代價 | 做出沒辨識度的通用畫面 → 整份返工 1-2 小時，甚至重做 |

**這是穩定性最便宜的投資。**
