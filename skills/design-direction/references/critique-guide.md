# 設計評審深度指南

> `design-direction` §評審 的詳細參考。提供評分標準、場景側重、常見問題清單。

---

## 評分標準詳解

### 0. 概念／立意（Concept）· 權重最高

先問「這個設計有沒有一個 idea」，再看做得好不好。為什麼放第 0 位：執行是放大器，放大一個空洞的概念只會更空洞。

| 分數 | 標準 |
|------|------|
| 9-10 | 有一個從真實內容裡長出來的獨有 idea，視覺母題不可替換 |
| 7-8 | 有明確立意，母題與內容相關但換個近似主題也勉強能用 |
| 5-6 | 只有風格沒有概念：好看，但沒說任何東西 |
| 3-4 | 通用樣板套皮，概念層為零 |
| 1-2 | 連風格都沒選對，純裝飾堆砌 |

**核心問題清單**：
- 這個設計說了什麼？能用一句話講出它的 idea 嗎？講不出來就是沒有
- 蓋住所有文字和 logo，還認得出主題嗎？認不出說明視覺沒承擔表達（文字即母題的排版設計除外，改問：這套文字處理換個主題還成立嗎）
- 換個客戶名／產品名還成立嗎？**成立 ＝ 樣板，本維度直接 ≤5 分**
- 形式有沒有來自內容的獨有視覺母題？（呼應 SKILL.md §核心哲學 1「從既有 context 長出來，不憑空畫」：形式該從內容與該區設計語言推出來，不是從風格庫裡抽）

**一票否決規則**：概念 ≤5 分時，總評封頂 6.0（良好檔下限）。後面 5 個維度全是 execution，execution 再精緻也拉不回一個沒有 idea 的設計——那只是把樣板打磨得更亮。

### 1. 哲學一致性（Philosophy Alignment）

**這一維有兩條判準路徑，先看 `design.precedent` 是哪一邊**：

| `precedent` | 對照物 |
|---|---|
| **`false`**（無先例，走風格庫） | 對照 `design-styles.md` 該條目標示的參考案例、視覺 DNA 與還原度 |
| **`true`**（該區已有設計語言） | 對照 `design-language` 抄出來的 token 體系——色彩／字型／版面／元件是否自洽 |

| 分數 | 標準 |
|------|------|
| 9-10 | 完整體現對照物的核心精神，每個細節都有依據 |
| 7-8 | 整體方向正確，核心特徵到位，個別細節偏離 |
| 5-6 | 能看出意圖，但執行時混入了其他來源的元素，不夠純粹 |
| 3-4 | 僅在表面模仿，未理解內核 |
| 1-2 | 與對照物基本無關 |

**評審要點**：
- `precedent=false`：條目裡標示的「標誌元素」有沒有真的出現？還原度低於條目標示值的部分，有沒有明說是降級？
- `precedent=true`：色值、字級、間距是不是**抄自實際檔案的 exact values**，還是憑印象重畫的近似值？有沒有拿別區的 token 頂替？
- 兩邊共通：有沒有「自相矛盾」的元素？（例如選了極致留白路線卻塞滿內容）

### 2. 視覺層級（Visual Hierarchy）

| 分數 | 標準 |
|------|------|
| 9-10 | 視線自然沿設計者意圖流動，資訊取得零摩擦 |
| 7-8 | 主次關係清晰，偶有 1-2 處層級模糊 |
| 5-6 | 能分出標題和正文，但中間層級混亂 |
| 3-4 | 資訊平鋪，沒有明確的視覺入口 |
| 1-2 | 混亂，讀者不知道先看哪裡 |

**評審要點**：
- 標題與正文的字級對比是否足夠？（至少 2.5 倍）
- 顏色／粗細／大小是否建立了 3-4 個清晰層級？
- 留白是否在引導視線？
- 「瞇眼測試」：瞇起眼看，層級是否仍然清晰？

### 3. 細節執行（Craft Quality）

| 分數 | 標準 |
|------|------|
| 9-10 | 像素級精確，對齊、間距、顏色無任何瑕疵 |
| 7-8 | 整體精緻，有 1-2 處微小對齊／間距問題 |
| 5-6 | 基本對齊，但間距不統一，顏色使用不夠系統 |
| 3-4 | 明顯的對齊錯誤、間距混亂、顏色過多 |
| 1-2 | 粗糙，看起來像草稿 |

**評審要點**：
- 是否使用了統一的間距系統（例如 8pt 網格）？
- 同類元素的間距是否一致？
- 顏色數量是否受控？（通常不超過 3-4 種）
- 字型家族是否統一？（通常不超過 2 種）
- 邊緣對齊是否精確？

### 4. 功能性（Functionality）

| 分數 | 標準 |
|------|------|
| 9-10 | 每個設計元素都服務於目標，零冗餘 |
| 7-8 | 功能導向明確，有少量可刪減的裝飾 |
| 5-6 | 基本可用，但有明顯的裝飾性元素分散注意力 |
| 3-4 | 形式大於功能，讀者需要努力尋找資訊 |
| 1-2 | 完全被裝飾淹沒，失去了傳達資訊的能力 |

**評審要點**：
- 刪掉任何一個元素，設計會變差嗎？（如果不會，就應該刪）
- CTA／關鍵資訊是否在最顯眼的位置？
- 是否有「因為好看所以加上去」的元素？
- 資訊密度與頁面目的是否匹配？

### 5. 創新性（Originality）

| 分數 | 標準 |
|------|------|
| 9-10 | 令人耳目一新，在既定框架內找到了獨特表達 |
| 7-8 | 有自己的想法，不是簡單的樣板套用 |
| 5-6 | 中規中矩，看起來像樣板 |
| 3-4 | 大量使用了 cliché（例如漸層圓球代表 AI） |
| 1-2 | 完全是樣板或素材拼湊 |

**評審要點**：
- 是否避開了常見 cliché？（見下方「常見問題清單」）
- 在遵循設計方向的同時是否有自己的表達？
- 是否有「意想不到但很合理」的設計決策？

## 場景評審側重

不同頁面類型的評審重點不同（概念維不在表內：它對所有場景都是第一道關，不參與側重取捨）：

| 場景 | 最重要維度 | 次重要 | 可放寬 |
|------|-----------|--------|--------|
| 落地頁／官網 | 功能性、視覺層級 | 創新性 | —（全面要求） |
| App／Web UI | 功能性、細節執行 | 視覺層級 | 哲學一致性（可用性優先） |
| 文件／知識庫 | 視覺層級、功能性 | 細節執行 | 創新性（清晰優先） |
| 作品集／品牌宣言頁 | 創新性、視覺層級 | 哲學一致性 | 功能性（表達優先） |

## 常見設計問題 Top 9

### 1. AI 科技 cliché
**問題**：漸層圓球、數字雨、藍色電路板、機器人臉
**為什麼是問題**：讀者已經對這些視覺疲勞，無法區分你和其他人
**修復**：用抽象隱喻替代直白符號（例如用「對話」的隱喻而非聊天氣泡圖示）

### 2. 字級層級不足
**問題**：標題和正文差距太小（<2.5 倍）
**為什麼是問題**：讀者無法快速定位關鍵資訊
**修復**：標題至少為正文的 3 倍（例如正文 16px → 標題 48-64px）

### 3. 顏色過多
**問題**：使用 5 種以上顏色，沒有主次
**為什麼是問題**：視覺混亂，品牌感弱
**修復**：限制為 1 個主色 ＋ 1 個輔色 ＋ 1 個強調色 ＋ 灰階

### 4. 間距不統一
**問題**：元素間距隨意，沒有系統
**為什麼是問題**：看起來不專業，視覺節奏混亂
**修復**：建立 8pt 網格系統（間距只用 8／16／24／32／48／64px）

### 5. 留白不足
**問題**：所有空間都被內容填滿
**為什麼是問題**：資訊擁擠導致閱讀疲勞，反而降低資訊傳達效率
**修復**：留白至少占總面積 40%（極簡風格 60%+）

### 6. 字型過多
**問題**：使用 3 種以上字型
**為什麼是問題**：視覺噪音，削弱統一感
**修復**：最多 2 種字型（1 種標題 ＋ 1 種正文），用字重和大小創造變化

### 7. 對齊不一致
**問題**：有的靠左，有的置中，有的靠右
**為什麼是問題**：破壞視覺秩序感
**修復**：選定一種對齊方式（推薦靠左），全域統一

### 8. 裝飾大於內容
**問題**：背景圖案／漸層／陰影搶了主要內容的風頭
**為什麼是問題**：本末倒置，讀者是來看資訊不是看裝飾
**修復**：「如果刪掉這個裝飾，設計會變差嗎？」如果不會，就刪

### 9. 賽博霓虹濫用
**問題**：深藍底（#0D1117）＋ 霓虹色發光效果
**為什麼是問題**：這是預設審美禁區（見 `design-styles.md` §預設審美禁區），且已成為最大的 cliché 之一——該區品牌本來就這樣用時可 override
**修復**：選擇更有辨識度的配色方案（參考 `design-styles.md` 的 20 種風格色彩系統）

## 評審輸出樣板

```
## 設計評審報告

**總體評分**：X.X/10 [優秀(8+)/良好(6-7.9)/需改進(4-5.9)/不合格(<4)]
（概念 ≤5 時總評封頂 6 分，先修概念再談執行）

**分項評分**：
- 概念／立意：X/10 [這個設計的 idea 是什麼？一句話講出來]
- 哲學一致性：X/10 [一句話說明，並標明走的是 precedent true 還是 false 判準]
- 視覺層級：X/10 [一句話說明]
- 細節執行：X/10 [一句話說明]
- 功能性：X/10 [一句話說明]
- 創新性：X/10 [一句話說明]

### 優點（Keep）
- [具體指出做得好的地方，用設計語言描述]

### 問題（Fix）
[按嚴重程度排序]

**1. [問題名稱]** — 致命 / 重要 / 優化
- 當前：[描述現狀]
- 問題：[為什麼這是問題]
- 修復：[具體操作，含數值]

### 快速修復清單（Quick Wins）
如果只有 5 分鐘，優先做這 3 件事：
- [ ] [最有影響力的修復]
- [ ] [第二重要的修復]
- [ ] [第三重要的修復]
```
